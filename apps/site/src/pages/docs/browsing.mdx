# Browsing

## Views

How a file is shown depends on its type; every [served file](/docs/usage#files) opens:

- Markdown opens in Source. Choosing Preview opens other documents in the
  project in Preview until you choose Source, for the rest of the browser tab.
  Images open in Preview; SVG also has Source.
- JSON/YAML open in Source; Format shows a formatted, highlighted view on
  demand. Invalid files stay readable and searchable in Source.
  YAML formatting retains comments, anchors/aliases, scalar styles, and all
  documents; spacing and comment placement can change in the formatted view.
- HTML, CSS, and JavaScript also open in Source with Format on demand. Format
  only reindents and breaks lines: comments, strings, and values are kept
  verbatim, as are `pre`, `textarea`, `script`, `style`, and inline SVG
  content. HTML tag and attribute names show lowercase. JavaScript containing
  JSX or that fails to tokenize keeps Source with a format notice.
- Known languages and config files show highlighted source, highlighted in
  the browser with WebAssembly. Unknown text files, and Fish, INI,
  Properties, and reStructuredText files, show plain text.
- Mermaid diagrams render as themed SVG with ondine, in Markdown fences and
  `.mmd`/`.mermaid` files (open in Preview); expand to zoom and pan.

Formatting is read-only; original files stay unchanged.

Markdown Preview hides leading frontmatter enclosed by matching `---` (YAML) or
`+++` (TOML) lines, and HTML comments. Source preserves both. Unclosed frontmatter
stays visible; comment syntax inside code stays literal.

## Binary and large files

- Binary files (a NUL byte in the first 8000 bytes) other than images show a
  "Binary file" note and are excluded from content search.
- Files over 4 MiB show plain, unhighlighted source without preview or
  formatting; image previews stay available. Files over 8 MiB are also
  excluded from content search.
- Non-image files over 32 MiB are not read; they show a "Too large to display"
  note.

## Explorer and tabs

- Switch between Explorer, Search, and Source Control from a VS Code-style
  activity bar (Cmd/Ctrl+Shift+E, Cmd/Ctrl+Shift+F, Cmd/Ctrl+Shift+G); click
  the active item or press Cmd/Ctrl+B to hide the sidebar.
- Navigate files in a compact, resizable tree.
- Filter file names and paths with Pierre Trees (Cmd/Ctrl+P; Cmd/Ctrl+K alias).
- Keep visited documents in a borderless editor-style tab bar. The active tab
  joins the document surface. Inactive close buttons appear on hover or keyboard
  focus; touch devices keep them visible. Right-click a tab to close it, other
  tabs, tabs to its right, or all tabs, or to show a file's history.
- Right-click a file or folder in the Explorer to copy its full or relative
  path; a file's menu also has **Show File History**.

### Back and forward

The arrows before the tabs go back and forward through the places you
visited: tabs you switched to, definitions and search results you opened, and
walkthrough steps. Each arrow's tooltip names where it leads, including the
project when it is another one. Going back to a tab you closed opens it again.

- **Ctrl+Alt+-** goes back and **Ctrl+Shift+-** goes forward (**Ctrl+-** and
  **Ctrl+Shift+-** on macOS), as in VS Code. The browser's own back and
  forward move through the same history.
- Right-click or hold an arrow to list up to 12 places in that direction and
  jump to one.
- **Go Back**, **Go Forward**, and **Recent Locations** are in the command
  palette. Recent Locations lists each place once, most recent first; type to
  filter and press Enter to open it.

The history belongs to the browser tab and survives a reload. Phones hide the
arrows; use the browser's back.

## Line links and paths

- Select lines or ranges from the line numbers (drag or Shift-click) to copy
  `path:12-20`; share `#L12-L20` links that open with the range highlighted.
- Diffs select lines the same way and copy the side's own lines: `path:12-20`
  for the new side, HEAD's (or the parent commit's) numbers for deleted lines.
  Links name the file and side: `#f=src/App.tsx&R12-R20` for the new side,
  `&L5` for the old; they open scrolled to the lines, expanding unchanged
  lines they name.
- Step through a review's changes with `n` and `p`, F7 and Shift+F7, or the
  toolbar's Previous change and Next change; steps cross into the next or
  previous file and select the changed lines, so their link and
  `path:12-20` copy are one click away. The status bar shows where the
  change sits in its file: "Change 2 of 5".
- Copy the open file's or reviewed file's path from the status bar.

## Search

Search file content in the Search view (Cmd/Ctrl+Shift+F or Find in files in
the status bar) like VS Code: every match grouped by file, Match Case, Match
Whole Word, and regular expressions, files to include/exclude globs, and
F4/Shift+F4 to step through matches. Files git ignores are skipped, including
global excludes and linked-worktree excludes.

## Source Control

Source Control stacks three panes, always in this order:

- **Uncommitted** counts and lists every modified, added, untracked, deleted,
  or renamed file since the last commit, as a flat list or a tree. Click a
  file to review it. A changed file's Source marks its changes beside the line
  numbers: a green bar for added lines, a blue bar for modified ones, and a
  red wedge where lines were deleted. Hover a mark to name the change; click
  it to open the Uncommitted review at that line.
- **Commits** lists your branch's commits since it left its base, or the whole
  history with All, 50 at a time. On the base branch itself it always shows
  the whole history. Click a commit's chevron, or press Right, to show its
  message, author, date, hash, and the stacked branches it tips. The field
  at its top filters commits by message, author, or hash prefix; Escape
  clears it.
- **Branches** shows your branch stack: the branches between the base and
  your checkout, any built on top of it, and the base at the merge-base. Each
  branch has its own color, and its commits in Commits carry it as a stripe
  along their edge.

Empty panes start closed; open or close any pane and Zero remembers it.
Drag between open panes to resize them. The base defaults to `origin/HEAD`,
`main`, or `master`; click the base at the foot of Branches to pick another,
and Zero remembers it per project. Zero reads git data directly; `git` need not be
installed.

### File history and commit search

**Show File History**, in a file's Explorer or tab menu or the command palette
(**Source Control › Show File History**, for the file in view), filters Commits
to the commits that changed that file and shows it as a chip under the filter
field; remove the chip with its ×. Type in the field to also match a commit's
message, author name or email, or the start of its hash (4 or more digits).
Branch and All still apply, so switch to All for a file's whole history.
Clicking a commit in a file's history opens its diff at that file. Press
Escape in the field to clear the filter and hide it.

A file's history compares each commit with its first parent, so a merge shows
when it brought changes to the file into the branch. It does not follow
renames: commits from before a rename don't show. Each page searches at most 10,000
commits; when a rare match leaves a page short, **Load more** (or **Search
older commits** when nothing matched yet) continues where it stopped.

Click a commit to open its diff. Shift-click another to review the combined
changes of every commit between them. Arrow keys move through commits without
opening them; press Enter to open the selection. Expand a commit with its
chevron to see its message, author, and changed files; click a file to open
the diff at it. Escape narrows a range back to one commit, and Cmd/Ctrl+C
copies a commit's hash. On a branch, one
button reviews just that branch's own commits against the branch below it,
the other everything since the base.

Your checked-out branch's review against the base can also include your
uncommitted work. Its header switches between **Committed**, the commits only,
as a pull request shows them, and **+ Uncommitted**, everything from the
merge-base to your working tree. The tab switches in place, keeps the file in
view, and reads `vs main + uncommitted`; files with uncommitted edits carry a
dot. The review opens on Committed; with nothing uncommitted, + Uncommitted
stays disabled.

A review opens in one tab: every file's diff stacked under a sticky header,
loaded as you scroll, in the same order as the file list and tree. The
toolbar switches split or unified view, steps through changes, and expands
or collapses every file; View options holds wrap, ignore whitespace, word or
character inline changes, and expand unchanged. A renamed file with no line
changes reads "renamed". Commit, range, and branch reviews list their files
in a rail beside the diffs; drag its edge to resize it, or hide it with the
Files button. Filter the rail by path, or hide the files you have viewed;
Zero remembers Hide viewed.

Mark a file Viewed to fold it away and move on to the next file you have not
viewed; the rail checks viewed files and dims their names. When a viewed
file changes, it opens again and reads "Changed since viewed" until you mark
it again. Outside text fields, `n` and `p` go to the next and previous
change, `]` and `[` to the next and previous file, and `v` marks the file in
view Viewed or unmarks it.

Changed images (PNG, JPEG, GIF, WebP, and other raster formats) show both
versions side by side with their dimensions and size (2-up), or one over the
other: Swipe drags a divider across them, and Onion skin fades the new one
in. Added and deleted images show their one version. Images over 32 MiB, or
any that can't be read, show the binary file note instead.
Uncommitted and branch reviews follow new edits and commits; commit and range
reviews stay fixed. On phones, tap a commit to show its diff button,
long-press a commit and tap another to select a range, and use the Files
button to jump between a review's files.

## Live updates

Zero follows changes on disk in the project each tab shows. Save a file in
your editor, or let an agent write one, and the Explorer, the open document,
Source Control, and an open Search pick it up within a second or two. The
document keeps its scroll, selection, and view; a deleted file shows that it
is unavailable. Checkouts, commits, and branch switches update Source Control
too.

The status bar shows how the project is followed:

- **Live**: Zero watches the project's folders for changes.
- **Polling**: the project is too large to watch (more than 4096 folders, or
  8192 files and folders on macOS), or the system's watch limit is reached;
  Zero checks every few seconds instead.
- **Off**: Zero already follows 8 projects in other tabs, or the connection
  dropped; the project rereads when you return to its tab.

Only visible tabs follow their project: a background tab catches up when you
return to it. Skipped folders (`.git`, `node_modules`, `vendor`) and those
below `--depth` are not watched.

## Settings and commands

- Choose a theme (Zero Dark by default; Auto, Zero Light, Dracula, Solarized Light, and
  Omarchy's 23 built-in themes, such as Tokyo Night, Kanagawa, and Rose Pine)
  and interface font size in Settings (gear in the status bar, Cmd/Ctrl+,); search, browse categories,
  or filter modified preferences. Changes apply immediately and save in the
  browser.
- Run commands from a VS Code-style command palette (Cmd/Ctrl+Shift+P or F1);
  each setting is a command that opens Settings at it. Preferences › Color
  Theme previews themes as you arrow through them; Enter keeps one, Escape
  restores yours.
- The status bar shows document details; disclose process CPU/RAM from Ready.
