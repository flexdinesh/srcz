# Remote hosts

Zero runs beside the files. To browse another machine, start it there with
`--remote`, then run the command it prints on your computer. The
[desktop app](/docs/desktop) opens that machine in a window of its own.

## Install Zero on the host

Install the CLI alone on the remote machine; it needs no desktop app
([Getting started](/docs/getting-started)):

```sh
curl -fsSL https://raw.githubusercontent.com/flexdinesh/zero/main/scripts/install.sh | sh -s -- --cli-only
```

The script needs no sudo and puts `zero` in `~/.local/bin` (or `~/bin`).
Release archives (`zero_<version>_linux_<amd64|arm64>.tar.gz`) work too;
put `zero` in `~/.local/bin`.

## Serve from the host

```sh
zero ~/code/foo --remote
```

```text
  zero 1.4.0
  serving directory:  /home/dee/code/foo

  on your computer, run:
  zero connect 10.0.0.5:7971/<credential>

  stops 10 min after this if nothing connects, and 5 min after the last UI closes. `zero remote stop` stops it now.
```

It returns to your shell and keeps serving in the background, so you can close
the SSH session. It binds every interface unless `--host` names one, on the
first free port from 7971 to 7980 unless `--port` sets it. It serves every
directory Zero already serves on that machine, and prints them all.

Without `--remote`, `zero` on a machine with no UI (an SSH session, or Linux
without a display) prints a reminder and exits. It never opens a port by itself.

## Connect from your computer

```sh
zero connect 10.0.0.5:7971/<credential>
```

The desktop app opens that machine in its own window, with its own tabs and
settings. Connect to several machines and each gets a window. Zero saves the
connection, so `zero://<id>/` links reopen it. `--no-open` saves it and prints
the link instead.

The printed addresses are a guess at what your computer can reach: the address
your SSH session reached, then Tailscale addresses (they work from any network),
then the rest. If they are wrong, edit the string, or pass `--host` (a Tailscale
MagicDNS name works):

```sh
zero connect --host mybox 10.0.0.5:7971/<credential>
ssh -L 7971:localhost:7971 <host>
zero connect --host localhost 10.0.0.5:7971/<credential>
```

## Security

The string is a password: anyone who has it and can reach the port can read the
served files. Traffic uses TLS with a certificate pinned by the string, so a
machine pretending to be the server is refused, and every request carries the
string's token. The string has no expiry. It keeps working across restarts until
you replace it:

```sh
zero remote rotate    # old strings stop working
```

Pages from a remote server cannot reach your computer: they get no folder dialog
and no Reveal in File Manager, and cannot read another window's data.

## When it stops

The server stops 10 minutes after starting if no window or browser connects, and
5 minutes after the last one closes. A hidden or minimized window still counts.

```sh
zero remote status    # state, clients, and the string again
zero remote stop      # stop now
```

`--foreground` keeps the server in that command's process instead, with no
time limits: it stops with the process (Ctrl+C, SIGTERM). Use it in a
container or under a service manager:

```sh
zero ~/code/foo --remote --foreground
```

The `ghcr.io/flexdinesh/zero` image runs it; the README's Docker section has
the recipe.

## Browser

```sh
zero ~/code/foo --remote --web
```

also prints a `web:` link. Open it in any browser; it signs in with a cookie and
removes the token from the address bar. Browsers warn about the self-signed
certificate, because they cannot pin it. That link is a password too.

:::warning
`zero browser --host <address>` is a different thing: plain http with **no
authentication**. Anyone who can reach the address can read the served files. Use
it only on networks you trust, or run `zero browser` (it binds `localhost`) and
forward its port yourself, for example `ssh -L 7971:localhost:7971 <host>`.
:::

## Tailscale

On a [tailnet](https://tailscale.com), serve with real HTTPS and no string:

```sh
zero ~/code/foo --tailscale
```

```text
  zero 1.4.0
  serving directory:  /home/dee/code/foo

  tailnet:  https://mybox.tail1234.ts.net:7971/
  open it on any device your tailnet's access rules let reach this machine; they can all read the served files.

  stops 10 min after this if nothing connects, and 5 min after the last UI closes. `zero remote stop` stops it now.
```

Open the link in a browser on any of your tailnet devices. Zero runs
`tailscale serve` for you on HTTPS port 7971 (`--port` changes it) and stops it
with the server, so nothing stays in your Tailscale settings. It keeps the same
time limits as `--remote`, works with `--foreground`, and `zero remote status`
and `zero remote stop` manage it. It replaces a `--remote` listener, and the
reverse.

There is no token: your tailnet's access rules decide who can connect, and
anyone they let reach this machine can read and change what Zero serves. Zero
needs the Tailscale CLI, a connected tailnet, and HTTPS Certificates turned on
in the admin console's DNS page. On Linux, run
`sudo tailscale set --operator=$USER` once so `tailscale serve` runs as you.
Zero names whichever is missing.

Tailscale proxies to a port on `127.0.0.1`, which other users of the host can
reach, as they can `zero browser`.

## Notifications

A connection's window notifies you as a local one does
([Desktop app](/docs/desktop#notifications)), with its own settings. Each
notification starts with the connection's label, so you can tell it from one
about this computer. If the host goes away, they resume when it returns.

## Walkthroughs

Agents on the host publish with `zero walkthrough publish`
([Walkthroughs](/docs/walkthroughs)). While the host serves with `--remote`, it
prints a `zero://` link that opens on the connected computer.

## Containers

```sh
zero attach docker://web/src
```

```text
  installing zero in docker://web/src
attached to docker://web/src (zero 1.4.0 on 3f2a9c1b7d4e)
desktop: zero://s-5c1e0b7a2d94/
```

opens `/src` of the running container `web` in its own desktop app window.
Without a path, it serves the container's working directory. The container
needs no shell and no published port, only a writable `/tmp`: zero copies itself
into `/tmp/.zero` as the container's user and runs there through `docker exec`.
It uses your current Docker context, so remote Docker hosts work too.

The window runs zero in the container while it is open, and zero deletes its
copy when the window closes; it copies itself in again each time. `zero attach`
saves the container as a connection, like `zero connect`, so its link
(`zero://s-…/`) reopens it while the container runs. A container that stopped or
was replaced shows a page saying to run `zero attach` again. `--no-open` saves
it and prints the link.

With `--browser` or `--port`, without the desktop app, or on a machine with no
UI, it serves your browser instead:

```sh
zero attach --browser docker://web/src
```

```text
  installing zero in docker://web/src
  zero 1.4.0
  attached to:  docker://web/src (zero 1.4.0 on 3f2a9c1b7d4e)
  web:          http://127.0.0.1:7971/

  ctrl-c to stop.
```

and deletes the copy when you press Ctrl-C.

zero gets the copy from its image, `ghcr.io/flexdinesh/zero`, at its own
version, for the container's platform (linux amd64 or arm64), so the first
attach needs the network. Like `zero browser`, browser mode serves `127.0.0.1`
without authentication; `--port` and `--no-open` work the same.
