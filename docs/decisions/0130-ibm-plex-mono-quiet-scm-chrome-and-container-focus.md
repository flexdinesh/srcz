# 0130: IBM Plex Mono, quieter Source Control chrome, and no container focus rings

- Status: Accepted
- Date: 2026-11-11
- Supersedes: the system monospace stack of [0102](0102-sharp-slate-panes.md)
  and the site; [0104](0104-source-zero-logo.md)'s outlined JetBrains Mono
  wordmark; [0129](0129-base-row-picker-inline-commit-filter-and-lanes.md)'s
  lane rails and bordered branch and HEAD chips; [0123](0123-pane-headers-and-two-line-commit-rows.md)'s
  separate action row for pane actions
- Amends: [0122](0122-type-roles-and-list-size.md)'s 14px Inter file rows

## Context

The system mono stack is SF Mono on macOS and Liberation or DejaVu on Linux,
so chrome looked different on every machine, and its bold pane titles read
heavy. Source Control carried decoration that said little: an action row under
Uncommitted holding only icons, a 2px lane rail down every commit and branch,
and bordered chips for branch names and HEAD. In the desktop app, focusing a
container (the inline sidebar `<dialog>`, the document `main`) drew a 2px
accent ring around a whole pane.

## Decision

- **One mono face: IBM Plex Mono, bundled.** `@fontsource/ibm-plex-mono`
  (400 to 700) leads `--font-mono` in the web app, so chrome (tabs, view
  and pane titles, the title band), source, diffs, and code blocks share it.
  Bold syntax tokens need the real 700 face: without it Chromium substitutes
  a face whose line box grows a bold row 1px past Pierre's 22px estimate, and
  the review's reveal pin then fights the resize.
  The site bundles 400 to 700 and leads `--sz-mono`, `--l-mono`, and Vocs'
  `--vocs-font-family-mono` with it. The brand's outlined wordmark (lockups,
  docs logo, social card) is re-outlined from Plex Mono Bold, the card's
  tagline from Regular, at the same 600-unit advance, so layouts do not move.
- **File names in lists are mono at the source size** (`--text-file`, 13px):
  the Explorer, Source Control's change rows and trees, the review rail's
  tree, and Search's file rows. Folders and stats stay 12px sans.
- **Titles are quieter.** View, pane, and review rail titles are 12px mono
  500 in `text-secondary`.
- **Pane actions end the pane's header.** Uncommitted's actions sit at the end
  of its header band, always visible, beside (not inside) the header's toggle.
  Hover marks the whole band. Commits keeps its filter row.
- **Lanes are hue only.** Commits and branches draw no rail; a layer's lane
  colors its branch icon and its branch names at commits.
- **Branch names and HEAD are unboxed.** Branch names at a commit are 12px mono
  text in their lane's hue; HEAD's tag is 12px mono `text-muted`. The
  merge-base hash keeps its bordered chip.
- **Only controls ring.** Elements that are not controls (no `href`, form
  element, `summary`, `tabindex`, or `contenteditable`) and every `dialog`,
  `main`, and `section` draw no focus outline. The document pane (`main`,
  source, image) draws none either. Controls, including roving rows with
  `tabindex="-1"`, keep their keyboard rings.

## Consequences

- About 450 KB of font files embed in the binary (woff2 and woff for each
  subset and weight); browsers fetch only the woff2 subsets a page uses.
- Plex Mono's x-height is smaller than SF Mono's, so 13px source reads a touch
  smaller on macOS.
- A keyboard user who moves focus into the document pane sees no ring; the
  pane's content still scrolls and takes keys.
- Without rails, a commit's layer shows through its branch names and its
  position only.
- Brand rasters are regenerated by hand as before (decision 0108).
