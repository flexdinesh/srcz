# AGENTS.md

## Purpose

`zero` is a Go CLI and local server for browsing local files through an embedded Vite/React UI.

Read `docs/decisions/` before changing scope, file types, views, or limits. Record new decisions there; supersede rather than rewrite.

## Boundaries

- Layout (decision 0078): applications live in `apps/` (`zero`, `web`, `desktop`, `site`); shared packages in `packages/` (`contracts`, decision 0080); shared fixtures stay in `testdata/`; repository tooling stays at the root.
- Go CLI/server: the `apps/zero/` module (path `github.com/flexdinesh/zero`): `main.go`, `cmd/`, and `internal/`. The root `go.work` uses `apps/zero` and `tools` (its own module); run Go commands from the root with explicit package paths (`./apps/zero/...`, `./tools/...`).
- Local validation: `tools/validate/` owns committed/current-edit snapshots, host static checks, input certificates, admission, and artifacts; its `Dockerfile` and `compose.yaml` own all test execution and its preparation (decision 0110). Public mise tasks orchestrate; hidden `_host:*` and `_container:*` leaves never invoke public wrappers. PR publishing is separate. This tooling is not part of the shipped application.
- `apps/zero/cmd/` owns CLI validation, session configuration, application startup, and the `zero daemon` commands, including spawning a detached daemon. It also owns `zero walkthrough` (publish, schema) in `apps/zero/cmd/walkthrough.go` (decision 0065). Bare `zero [path]` opens the desktop app through the daemon and falls back to browser mode with a notice (`apps/zero/cmd/app.go`, decision 0068); `zero browser` always serves. On a no-UI machine (SSH session, or Linux without a display) bare `zero` prints advice and exits: it never opens a port. `zero <path> --remote` serves to other machines, `zero connect <string>` opens one in the desktop app, `zero remote status|stop|rotate` manage it (`apps/zero/cmd/remote.go`, `connect.go`, decision 0098). `zero attach docker://<container>[/path]` saves a sandbox connection and opens it in the desktop app like bare `zero`, else (`--browser`, `--port`, no UI, no app) serves a running container's files to the browser on `127.0.0.1`; hidden `zero serve-stdio <path>` is what runs inside (`apps/zero/cmd/attach.go`, decision 0127); hidden `zero connection stdio <id>` is what the desktop app runs for a saved sandbox: it installs again every run (`apps/zero/cmd/connection.go`, decision 0128). `zero <path> --tailscale` serves to the tailnet instead of `--remote`, through `tailscale serve` (decision 0126).
- `apps/zero/pkg/connection/` owns the connect string, credential, connection ids (`r-<12 hex>` remote, `s-<12 hex>` sandbox), transports (`Exec` runs a command and speaks the stdio wire over its pipes, decision 0127), and the 0600 store (`UserConfigDir/zero/connections.json`, version 2: `Saved` is a tagged union of `TLS` and `Sandbox`, unknown kinds kept; `Saved.Endpoint(zero)` is its one kind switch, decision 0128); the desktop app imports it. `apps/zero/internal/remote/` owns the TLS identity, token auth, compression, TCP listening, and reachable addresses. Neither knows when serving starts or stops; `internal/daemon` (`remote.go`) does (decision 0098). `apps/zero/internal/tailscale/` runs the `tailscale` CLI (PATH, then the macOS app): `Status` and a foreground `Serve` child, with errors that name their fix; it knows no web app or daemon (decision 0126).
- `apps/zero/internal/runtime/` owns the web app, HTTP server, and shutdown order (event streams end first, then in-flight requests get 5 s) shared by the CLI and the daemon. It knows no transport or listener.
- `apps/zero/internal/stdio/` serves a handler as HTTP/2 without TLS over one stream (stdin/stdout) and answers `RemoteInfo`; it knows no process. `apps/zero/internal/sandbox/` owns `Environment` (`Platform`, `Install`, `Exec`, `Identity`), `InstallDir` (`/tmp/.zero`), `ParseTarget`, and `Open`, whose one switch lists providers; `sandbox/docker` drives the `docker` CLI, found on PATH or in its install dirs (image `ghcr.io/flexdinesh/zero:<version>` for releases, else the local `zero-dev:<version>` that `scripts/install-dev.sh` builds, decision 0134; `docker cp --archive`, `docker exec --interactive`). `apps/zero/internal/attach/` is the provider-agnostic flow: platform check, install, `Exec` endpoint for `serve-stdio` (decision 0127).
- `apps/zero/internal/daemon/` owns the daemon (decisions 0061, 0066): per-user socket path, private directory and `flock` single instance, the `/_daemon/*` control API (intercepted before the web app: status, roots, covering open, the control event stream, walkthrough announcements, stop) as typed `Controller` operations plus its HTTP handler (decision 0080), `roots.json`, idle exit, the Go `Client`, and `Ensure`. Exposures (`exposure.go`) serve beyond the socket one at a time: `tls` (`remote.go`) and `tailscale` (`tailscale.go`, a loopback listener behind a `tailscale serve` child it starts through `internal/tailscale`; decision 0126). It knows no CLI flags and spawns no zero processes.
- `apps/zero/internal/app/` is the transport-agnostic application layer (decision 0080): per-domain services (`Projects`, `Documents`, `Events`, `SourceControl`, `Navigation`, `Metrics`, `Walkthroughs`, `Feedback`) whose operations take and return `pkg/contract` types and fail with `*app.Error` (kind, code, message). It knows no `net/http`; it owns project resolution (`ResolveProject`), indexed and commit document reads, image reads (`ReadImage`, 32 MiB), event subscriptions, Source Control (changes, diffs with their `lineDiff`, history, compares, compare stats and their budget; decision 0083), code navigation (indexed access checks and location mapping over `internal/lsp`), process metrics (decision 0085), and walkthroughs (publish, list, get with rendered narration, delete, schema, announcements, and the 0047 target checks, `NewWalkthroughTargets`, which the CLI shares; decision 0087), and review feedback (keys, side reads, re-anchored locations, Markdown, announcements; decision 0120).
- `apps/zero/pkg/contract/` is the single source of truth for transport shapes: JSON bodies (field order is wire order), `ErrorResponse`, error kinds (`HTTPStatus`/`KindForStatus`) and codes, request parameters, and stream events. Cross-field invariants are `//contract:rule` lines on the type.
- `apps/zero/pkg/client/` is the Go client: one `Client` interface over HTTP/TCP (`NewTCP`), HTTP/Unix socket (`NewUnix`), and in process (`pkg/client/inprocess`, `internal/app` plus an optional `daemon.Controller`; its own package so HTTP-only clients link no server, decision 0084); one parity suite covers all three.
- `tools/contracts/` generates `packages/contracts/src` (`@zero/contracts`: TypeScript types and guards without `as`, `any`, or `!`) from the `pkg/contract` files it lists as generated; every other contract file is listed Go-only. Never edit the output: run `mise run contracts:generate`; `contracts:check` (repo group) fails on drift.
- `apps/zero/internal/files/` owns traversal, the always-skipped `.git`, `node_modules`, and `vendor` directories (`Excluded`), depth, base-name globs (`NameFilter`), gitignore marking, and safe indexed-path resolution. It also exports the 0023 ignore rules (`IgnoreRules`), an unscoped walk of non-ignored files (`WalkUnignored`), root-confined `ResolveFile` for changed paths, and the directories a scan reads (`Directories`) for live updates. Accept an explicit matcher; know no file formats.
- `apps/zero/internal/projects/` owns the served-root set (`RootSet`: ordered, concurrency-safe; `Add` enforces 0009 rules), repository/worktree discovery, and project-directory resolution within the roots (repositories open whole) or standalone (`ResolveStandalone`: the directory is its own root). It knows the `.git` marker, git's worktree and `HEAD` files, where git state lives (`ReadGitState`: HEAD, index, refs), and the `origin` remote URL only.
- `apps/zero/internal/git/` owns go-git repository opening, HEAD tree and index reads, working-tree change detection against HEAD or HEAD's merge base with a base branch, exact rename pairing, HEAD blob reads, base-branch detection and branch listing, bounded commit walks (`base..HEAD` and full history), commit-to-first-parent file changes, bounded merge-base and branch/commit-range tree changes (a branch compare's head may be any local branch), bounded branch-stack detection, and commit blob reads. It knows git formats only; no HTTP or document policy.
- `apps/zero/internal/diff/` owns line diffs (decision 0083): hunks, blocks, collapsed gaps, and counts laid out exactly as jsdiff and Pierre lay them out (Myers search with jsdiff's tie-breaks, context 4, similarity realignment), the search time and change-run bounds, and numstat counts (`Count`). It knows bytes only.
- `apps/zero/internal/document/` owns file-type metadata (including each family's highlight language and image media types), lookup, previews, formatting, binary/size policy (`Available`), and document-link policy. Handlers receive bytes/context; never perform filesystem or HTTP work.
- `apps/zero/internal/lsp/` owns language-server data (`Builtins()`), host-specific install guidance, binary discovery, process lifecycle (start on demand, idle stop, failure backoff), and the JSON-RPC client. It knows absolute paths and LSP positions only; `apps/zero/internal/app/` validates indexed project access and maps locations to transport responses. Language servers own all symbol resolution.
- `apps/zero/internal/web/` is the HTTP adapter: routing, the Host check (`HostPolicy`: localhost and IP literals, plus a listener's `AllowedHosts`; decision 0126), CSP, JSON encoding, `app.Error` kind-to-status mapping, server-sent events, raw byte streaming, and the walkthrough write guards (Origin, JSON content type, 1 MiB body) for `internal/app`; it owns no domain. Every JSON error is `errorResponse` (`contract.ErrorResponse`, `{error, code?}`). Delegate format behavior to document handlers.
- `apps/zero/internal/walkthrough/` owns the walkthrough model, strict decoding, structural validation, the JSON Schema, the user-cache store, and `Service` (publish, list, get, delete), which every transport shares. It knows no HTTP and no git; `apps/zero/internal/app/` implements its `Targets` check against the index and git (decisions 0047, 0087).
- `apps/zero/internal/feedback/` owns the review feedback model, strict decoding, validation, pure anchor capture and resolution, blob hashes, the user-state store (per-ID `flock`, atomic replace, eviction), ID generation, and `Service`. It knows no HTTP and no git; `apps/zero/internal/app/feedback.go` derives the repository and branch key and reads sides (decision 0120).
- `apps/zero/internal/watch/` owns live updates (decisions 0050, 0066): the subscription hub, open and watched lease levels, one shared reference-counted fsnotify watcher, per-project debounce, the stat-poll fallback, and watch limits. It knows absolute paths only; `apps/zero/internal/app/` (`events.go`) composes each project's target from `files.Directories` and `projects.ReadGitState`, and `apps/zero/internal/web/` streams `/api/events`.
- `apps/zero/internal/control/` owns authenticated discovery (`List`, `Lookup`) and shutdown of local zero processes; `apps/zero/internal/browser/` opens the browser; `apps/zero/internal/desktopapp/` detects the desktop app's `zero://` handler, opens URLs in it, and gives per-OS install hints (never installs anything); `apps/zero/internal/version/` reports the build version.
- `apps/desktop/` is the desktop app (decisions 0094, 0095): its own Go 1.27 module outside `go.work` (mygo v0.7.4), binary `zero-desktop`, scheme `zero://`, one instance per user. The whole window is `apps/web` in the OS web view (WebKitGTK 4.1 on Linux, `linux.webview` in `mygo.json`); it embeds no frontend and draws no UI. From zero it imports only `pkg/contract`, `pkg/client`, and `pkg/connection` (`replace => ../zero`); `boundary_test.go` enforces it. One window per connection, each its own host and storage (decision 0098). `internal/proxy` serves `zero-app://local` from the daemon socket and `zero-app://<connection>` from a pinned TLS server or a sandbox's `Exec` endpoint (bundled `zero connection stdio <id>`, decision 0128), one `Upstream` per host through a `Resolver`, whose transport the window's notifier shares (`Connections.Endpoint`) and which ends with its window (`Drop`) (`/_daemon`, `/_zero` refused; header allowlist; Host and CSP treatment; a 5 s keepalive on event streams, because mygo cancels a request only on a failed write). `internal/bridge` is the pure payload validation of `window.zeroDesktop` (v2 methods `openFolder`, `showContextMenu`, `revealPath`, `showAppMenu`, `configureNotifications`, `setAppearance`, in `bridge.go` over mygo IPC, with a sender check; remote pages get no `openFolder` or `revealPath`). `internal/appearance` (decision 0119) remembers each connection window's theme-color background and appearance in `appearance.json`; only macOS hides the title bar (the page's `TitleBar` band) and applies the appearance through `Theme.SetSource`. `internal/connect` ensures the daemon with the bundled `resources/bin/zero` and ensures again when it has gone (`Daemon.Do`, `StreamClient`); `internal/link` parses links and arguments. `internal/notifier` (decision 0099) decides notices, one `Notifier` per connection window holding its own `/api/events` streams through `client.Client`, so both transports are one code path; it knows no mygo, and `notices.go` shows what it decides. On Linux the install scripts own only `zero-desktop/app`: WebKit keeps page state beside it. Not ported, on purpose: ssh, the Connect page, Open at Login, recent folders, the Dock menu, folder drop, file manager actions, deb and AppImage. `zero://` hosts are `local` or a connection id; addresses and secrets are invalid in a link. The word mygo means only the framework: the dependency and imports, `mygo.json`, its CLI.
- Frontend source: `apps/web/`. `apps/web/src/` keeps `main.tsx`, `router.tsx`, `App.tsx` (composition only), and `style.css` (import manifest and cascade layers only) at its root; `styles/` holds tokens, themes, base, layout, and print CSS; `components/ui/` holds the UI primitives; `gallery/` is the dev-only primitive gallery (`/__ui` in `pnpm dev:mock`); `api/` holds the HTTP adapter (`http.ts`), transport contracts, and data adapters; `features/<feature>/` holds each feature's views, hooks, and pure logic; `highlighting/` is shared by documents and diffs; `workspace/` holds tabs, memory, sidebar, status bar, and palette; `settings/` holds settings and their providers; `lib/` holds shared helpers.
- Every API read goes through `fetchJSON` in `apps/web/src/api/http.ts`, which turns network, non-JSON, server-rejected, and invalid responses into user-facing errors. Validate generated shapes with the guards from `@zero/contracts`; hand-written `*-contract.ts` guards remain only for shapes not yet in `pkg/contract`'s generated files. The one data stream, `/api/events`, is an `EventSource` in `apps/web/src/features/live-updates/use-live-updates.ts`; validate its events with `apps/web/src/api/events-contract.ts`. `/api/presence` carries no data: over TCP it marks a UI as open, and it stays open while the page is hidden (`use-presence.ts`, decision 0098).
- React owns interaction and presentation. Use server metadata for file families and view capabilities; never duplicate extension detection in the UI.
- User docs site: `apps/site/` (Vocs, static, build-time only; `docs/decisions/0026-vocs-user-docs-site.md`, `0074-landing-page-and-cloudflare-pages.md`, `0103-site-on-workers-static-assets.md`, `0105-walkthrough-landing.md`, `0106-feature-rows-landing.md`, `0107-docs-redesign.md`). The marketing landing is `/` (`apps/site/src/pages/index.mdx`, `layout: blank`, React in `apps/site/src/landing/` with scoped `landing.css`): a hero row and feature rows (`features.ts`, `Features.tsx`), each copy beside its HTML-built synthetic app pane (`panes.tsx`); docs live under `/docs` (`apps/site/src/pages/docs/`); `apps/site/src/pages/_root.css` restyles Vocs on every page except the landing's code, `_slots.tsx` renders the docs footer band, and `patches/vocs@2.10.3.patch` puts the theme toggle in the header; every docs page sets `showAskAi: false` (decisions 0102, 0105, 0106, 0107). Cloudflare Workers Static Assets serves `apps/site/dist/public` (`apps/site/wrangler.jsonc`). Contributor docs stay in `docs/`.
- `apps/zero/internal/web/dist/` is generated by `pnpm build:web`; never edit or commit it. Run `mise run build:web` before host development builds. Validation builds private embedded assets in its image before Go tests and vet; validation never consumes host build outputs. No branch or tag carries it: release builds embed it in GitHub release assets only (`docs/decisions/0079-releases-edge-prerelease-and-install-scripts.md`); `scripts/install-dev.sh` builds it on the developer's machine through the ref's `mise run dist` (decision 0134).

## Patterns

- Capabilities over type switches: the server declares `previewKind`, `formattable`, page-level `navigationSupported`, `binary`, `previewDisabled`, `searchExcluded`, `tooLarge`; the UI derives modes and views from them in `document-view.ts`.
- Optional interfaces: add behavior as a small interface (e.g. `Formatter`) that the registry detects and reports, not as flags handlers must remember.
- One composition point: `Builtins()` lists every family explicitly; a family's metadata is data, its behavior is its handler.
- Fail closed at startup: invalid registrations panic in `Builtins()`; invalid CLI input errors before serving.
- On-demand work: expensive or optional transforms (Format) get their own endpoint; `/api/page` stays cheap.
- Pure decision functions: keep view/mode logic and glob matching pure and unit-tested; components only render.

## Contracts

- Define families through `document.Type` and behavior through `document.Handler`: `Type` and `Preview`. Content search reads original source; handlers know nothing about it. Formatting is the optional `document.Formatter` capability; the registry derives `formattable` from it. `internal/web` composes language servers from `lsp.Builtins()` for the registered text families; `internal/app` derives page-level `navigationSupported` from them; document handlers know no code-navigation behavior.
- Declare extensions/filenames, language, preview kind/label, and default mode explicitly. Preview kinds are `markdown` and `image`; types without one default to Source.
- Validate composition with `NewRegistry`; reject duplicate/ambiguous IDs, extensions, and filenames, missing or malformed languages, and invalid view policies. Web tests reject languages Highlights does not know.
- Treat handler output as a contract: escape file text in preview/highlight HTML; leave input bytes unchanged; preserve source and search access on preview errors.
- Define transport shapes in `apps/zero/pkg/contract` and regenerate `packages/contracts` (`mise run contracts:generate`); never hand-write a guard for a generated shape. Keep the Go-only shapes with hand-written guards aligned by hand (`apps/web/src/api/events-contract.ts` for `events.go`). Keep `testdata/api` fixtures valid for both. Validate unknown transport data before use; preserve strict TypeScript safety.
- Domain operations live in `internal/app` and return contract types or `*app.Error`; transports only map them. Logic every client needs belongs on the server, presentation in clients; each move measures zero RSS before and after (decision 0080).

## System Design

- Compose families explicitly in `apps/zero/internal/document.Builtins()`. Registration decides presentation only; every in-scope file is browsable. Lookup: exact base name, then extension, then the plain-text fallback. The browser highlights the declared language with Highlights (decision 0029); never guess types.
- Reuse `CodeHandler` for highlighted source and `FormattedCodeHandler` for formatted text. Implement a specialized handler only when behavior requires it. Source-only additions should need no discovery, HTTP, or frontend format branches.
- Prefer cohesive packages, small semantic interfaces, and explicit dependencies. Avoid global registries, scattered file-type switches, and speculative plugin frameworks.
- Follow "Adding Languages and File Types" below; preserve the single-binary distribution.

## Encapsulation

- Keep parsing and formatting inside the owning handler. Keep code intelligence in installed language servers. Share highlighting and code-view behavior through existing document primitives.
- Keep filesystem safety in `apps/zero/internal/files/`; renderers must not bypass indexed-path resolution.
- Keep UI filter state separate from server scope and document/tab state. Consume declared capabilities rather than inspecting filenames or inferring behavior from rendered HTML.
- Expose semantic operations through package/component contracts. Keep parser/renderer internals private; do not widen APIs solely for tests.

## Behavior

- Source shows original text. Formatting is read-only; preserve meaningful values and presentation, including JSON number precision/key order and YAML comments, scalar styles, anchors/aliases, and multiple documents.
- Malformed files remain readable and searchable. Highlighting falls back to escaped text when a language is unknown or tokenization fails or panics.
- Binary files (NUL in the first 8000 bytes) send no source and skip search. Over 4 MiB: no highlighting, format, or non-image preview. Over 8 MiB: also skip search. Over 32 MiB (non-image): not read; `tooLarge` note only.
- Every file within `--depth` is available; `.git`, `node_modules`, and `vendor` directories are always skipped (decision 0060). Tree filters only change visibility; preserve open tabs, the active document, expansion, and responsive state. Filename search intersects the tree filter; global content search covers every available file.
- Gitignored files stay browsable in the tree but are excluded from content search and returned navigation locations.
- Code navigation is Source-only and LSP-only. Follow VS Code bindings. Binary files and files over 4 MiB do not navigate. No local parsing, symbol index, import guesses, or syntax fallback. Keep only indexed, in-scope, non-ignored project locations; preserve UTF-16 ranges.
- Language servers are enabled by default per browser, authorized per request with `X-Zero-Language-Servers: on`, started only by navigation, stopped after 10 idle minutes, and closed with zero. Status requests never start servers. Show unsupported, missing, disabled, starting, ready, and failed states beside the language label; missing servers show host-specific install instructions.
- Memory footprint is a priority: measure zero RSS and language-server process-tree RSS separately before and after navigation changes. Bound open documents, response sizes, startup/query time, and cancellation.
- Source Control is repository-scoped and lives in `internal/app` (decision 0083): `--depth` and the always-skipped directories do not apply. It reads worktree files only for paths validated against the change set, through `files.ResolveFile`; HEAD sides come from `apps/zero/internal/git/`. Commit history (0027) is repository-scoped too; commit diffs read both sides from git objects, validated against the commit's change set. 0004 limits apply per diff side. Compare stats (0035) count both sides under the same limits within a 64 MiB per-request budget. Diffs carry the server's `lineDiff` (hunks, blocks, gaps, counts); the web app lays it out for Pierre and never diffs in the browser. Never run the `git` binary.
- The daemon (0061) listens on a Unix socket (0600 in a 0700 per-user directory; macOS and Linux), one per user under a `flock`, and exits after 30 idle minutes (no request in flight). Only `--remote` adds a TCP listener: pinned TLS plus a token, the app's routes only, gone 10 minutes with no first UI or 5 minutes after the last (0098). Clients block only on a protocol mismatch, never a release mismatch. Saved roots that are missing at start are skipped and kept. `/_daemon/open` serves a path, replacing served roots inside it; `/_daemon/events` announces walkthroughs and keeps the daemon alive while open (0066). Browser memory keys by `sessionKey` (`daemon`, or the CLI's roots).
- Live updates (0050) follow only subscribed projects: a visible tab's `/api/events` stream is its interest; the server keeps no current project. Watch what a scan reads plus git state; past 4096 directories (8192 entries on kqueue) or on a watch failure, poll. Bound followed projects (8), paths per change (256), and stop a project 30 s after its last subscriber. Streams hold `lease=open` (default) or `lease=watched` (git state only, 16 projects, never lists the tree; 0066); an open project drops to watched 30 s after its last open stream. Every checkout stream sends `head` (baseline, then on moves).
- Keep Markdown image dependencies separate from browsable-document scope while enforcing root confinement. Serve raw bytes only for image-preview types, sandboxed.
- Test semantic behavior across boundaries: lookup/scope, direct access, source preservation, preview/format failures, binary/size limits, search, and UI navigation. Include source-only composition coverage when changing extension contracts; avoid tests tied to private implementation details.

## Adding Languages and File Types

Pick the smallest step that delivers the behavior. Each step is deliberate: no language guessing.

1. Source-only language (highlighting only): add one line to `Builtins()`, e.g. `source("zig", "Zig", "zig", []string{".zig"})`.
   - `Language` must be a Highlights language (`text` for none); fish, INI, Properties, and reStructuredText have no lexer and use `text`.
   - IDs, extensions, and filenames share one case-insensitive namespace; pick unused ones.
   - Add the family and its language to `testdata/document-families.json`. Tests fail until the fixture matches `Builtins()` and every language is a Highlights language (decision 0029).
   - No HTTP or contract change is needed.
2. Files identified by name (`Dockerfile`, `Makefile`): pass filenames as trailing args to `source(...)`. Without a Highlights lexer, add them to the `text` family instead.
3. Read-only Format: use `FormattedCodeHandler` with a `FormatSource` that copies input and preserves meaningful values. `formattable` and the Format button follow automatically.
4. New preview of an existing kind (`markdown`, `image`): implement `document.Handler` and register it. Escape HTML; keep Source available on preview errors.
5. New preview kind (e.g. table): this is a contract change. Update together:
   - `apps/zero/internal/document/registry.go` preview-kind constants and validation.
   - `apps/web/src/api/page-contract.ts` `previewKind` union and validator.
   - `apps/web/src/features/documents/document-view.ts` view kinds and `DocumentPane.tsx` rendering.
   - `testdata/api/default/` fixtures, `apps/web/dev-server.ts` mocks, and a decision record.
6. Code navigation: add an explicit `lsp.Builtins()` server entry for registered text families (launch command/args, LSP language IDs, prerequisites, host-specific install recipes, docs). `web.New` validates composition. Use real negotiated definition/reference capabilities; a language server does not imply every method is supported. No handler, HTTP type switch, or frontend extension detection is needed.
7. Test language-server behavior through `apps/zero/internal/lsp/lsptest` and a real-server smoke test when available. Include missing/failed/starting states, changes on disk, cancellation, and project confinement.
8. Binary formats with a viewer: declare an empty `Language` only for image-like families and extend `Type.HasTextSource`/`/api/raw` deliberately; never serve raw bytes for text families.

For every addition:

- Add a sample under `testdata/markdown/` and tests for lookup (extension, filename, fallback), highlighting, search, and preview/format failure where relevant.
- Keep `TestAPIFixturesMatchServerDocumentContract` green: fixtures must carry the registry's real `Type` JSON.
- Keep `TestDocumentFamiliesFixtureMatchesBuiltins` and `apps/web/src/highlighting/syntax-languages.test.ts` green: every family declares a Highlights language (`text` for none); raster images declare none.
- Update `apps/site/src/pages/docs` (and the README feature summary) when user-visible behavior changes. Tree and tab icons come from Pierre by file name; unknown names get the generic icon.

## Distribution

- The CLI must run from one self-contained Go binary. The desktop app is a separate artifact that bundles that binary (`resources/bin/zero`) and uses the OS web view (decisions 0094, 0095).
- Node, pnpm, and other JavaScript tooling are build-time only for the CLI. Optional, user-installed language servers may require their own runtimes; browsing never requires them.
- Build frontend assets before Go compilation and embed them through `apps/zero/internal/web/dist/`.
- Bundle runtime assets locally. Do not require a CDN, frontend sidecar, or external asset server.

## Conventions

- Make minimal, surgical changes.
- Zero's canonical identity is independent of the installed CLI filename. Local CLI help and recovery instructions use the invoked name; protocols, storage, bundled binaries, and version output remain canonical (decision 0118).
- Preserve strict TypeScript safety: no `any`, non-null assertions, or type assertions.
- Build UI from the primitives in `apps/web/src/components/ui/` (decision 0033). They are hand-owned React components with co-located CSS in `layer(ui)`; add a missing capability to the primitive instead of forking it in a feature. Never use raw `button`, `input`, `select`, `textarea`, or `dialog` outside `components/ui/`.
- Co-locate each feature's CSS beside it and import it from `style.css` in `layer(features)`. Use tokens from `apps/web/src/styles/tokens.css`: no color literals, raw font sizes, radii, z-indexes, durations, or px above 2. Tailwind stays for its theme and utilities; primitives do not use Tailwind classes.
- `pnpm lint` runs oxlint (Hooks rules, primitive-only elements) and stylelint (tokens only); both must report nothing.
- Format Go with `gofmt`; test behavior, not implementation details.

## Iteration

Report extended failures. `check:status` checks correctness coverage without running checks; `--suite extended|full` selects additional coverage. `--force` reruns checks and build steps while reusing compiler/download caches; a failed or cancelled active rerun revokes prior success for that input. Partial or extended results cannot certify correctness.

- Run long checks in the background and wait for the completion notification. Never poll logs or `sleep` in loops.
